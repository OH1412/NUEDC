# 透明传输协议与排障

## 为什么会黏包/分包

UART DMA、经典蓝牙 SPP 和 BLE GATT 都是字节流或分片传输。以下情况都
是正常的：

- 一个回调只收到半帧；
- 两帧一次到达；
- 一帧被拆成多个 BLE notification；
- 帧前混入上电噪声；
- 应用一次 write 在另一端被分段 read。

因此不能使用“本次收到的字节数”判断一条命令是否完整。

当前项目固定 8 字节：

```text
小车 -> 小电脑：76 + 6 字节数据 + 67
小电脑 -> 小车：92 + 6 字节数据 + 29
```

拆包器执行：

1. 环形缓冲区保存 DMA/中断收到的所有字节；
2. 状态机搜索合法帧头 `0x76` 或 `0x92`；
3. 收集到 8 字节；
4. 根据帧头验证对应帧尾；
5. 校验失败时重新搜索，不阻塞后续数据。

如果以后需要可变长度，建议升级为：

```text
SOF(2) + TYPE(1) + LENGTH(2) + SEQ(1) + PAYLOAD(N) + CRC16(2)
```

当前两次 MCU 完成帧完全相同。如果第一阶段 ACK 丢失后 MCU 重发，小电脑
可能已进入下一状态，并把重发误判成“左转完成”。因此当前验证版不要直接
加入完成帧重传。

比赛版建议至少让阶段可区分，例如：

```text
前进 1 m 完成：76 10 00 00 00 00 00 67
左转 90°完成：76 11 00 00 00 00 00 67
```

进一步增加序号和 CRC16 后，才能安全实现 ACK 超时、去重和有限次重发。

## 分层调试

1. MCU UART 和模块之间先用 USB-TTL 验证 AT。
2. 手机蓝牙助手连接，发送 ASCII，确认透明传输。
3. 改用 HEX 模式发送 8 字节帧。
4. Jetson 扫描/配对模块。
5. 用 `rfcomm` 或 BLE inspect 验证链路。
6. 最后启动 XML 行为树。

## 常见故障

### 能发现但不能出现 `/dev/rfcomm0`

模块可能运行在 BLE 模式，或 SPP channel 不是 1。执行：

```bash
sdptool browse AA:BB:CC:DD:EE:FF
```

查找 `Serial Port` 和 `Channel`。

### 手机能连，Jetson BLE 找不到数据特征

先运行 `ble_tool.sh inspect`，不要默认 UUID 是 FFE1。BT04 固件可能使用
FFB1/FFB2、FFE1 或厂商自定义 UUID。

### 数据乱码

检查 MCU UART 和模块透明传输波特率是否一致，确认都是 8N1，并确保
共地、逻辑电平正确。

### 电机启动后掉线

优先处理供电和电磁干扰：

- 蓝牙模块单独稳压/滤波；
- 模块旁加去耦；
- UART 线缩短；
- 天线远离电机线和金属；
- 电机端加合适的抑制和滤波。
