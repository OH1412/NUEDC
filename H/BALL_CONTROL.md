# H题钢珠位置控制

## 1. 坐标、角度和控制目标

控制内部统一采用：

- `x=0`：固定端零点；
- `x>0`：从零点朝电机端，范围 `0～0.25 m`；
- `theta>0`：电机端抬升，钢珠向零点滚，因此 `x` 减小；
- 控制器内部及终端输出单位：度；
- 发给电机的是升降位移毫米数，不是角度；
- 升降位移限制 `-99.99～+99.99 mm`，对应倾角限制约
  `-21.80°～+21.80°`。

因此控制模型的符号必须满足：

```text
theta > 0  =>  x_acceleration < 0
```

近似动力学为：

```text
x_dot  = v
v_dot  = -b*sin(theta) - c_c*tanh(v/v_eps) - c_v*v + d
```

车辆纵向加速度的正方向固定定义为从固定端（零点标定端）指向电机抬升端。
正车辆加速度会使钢球朝固定端运动，因此理想前馈为负倾角：

```text
theta_ff = -asin(a_cart / g)
```

串级PID把该倾角叠加到反馈角后再统一执行倾角限幅和相邻变化限制；MPC把
`a_cart`作为已知扰动直接加入预测模型。前馈默认关闭，当前只在
`H/longitudinal_acceleration.py` 中保留带时间戳的数据源接口，尚不打开
任何加速度串口。普通启动方式不受影响。

管道不同位置所需的静态保持角可以不同，而且不要求为0°。串级PID的速度环
积分会在当前目标附近自动保留一个小的非零保持角。MPC可用当前目标专属的
保持角初值或DOB估计局部恒定扰动；不能把一个位置测得的保持角强行套给整根
管道。配置中的 `equilibrium_angle_bias_deg` 只是缺省初值，每次启动可用
`--equilibrium-angle-bias-deg` 为本次目标单独覆盖。

`b` 是实际角度到滚动加速度的增益，`c_c、c_v` 分别表示集总库仑/滚动
阻力和速度相关阻力，`d` 是管道不水平、表面不均匀等形成的慢扰动。

理想实心钢球无滑动滚下平面时：

```text
b = 5/7*g ≈ 7.007 m/s²
```

不是质点模型中的 `g`。PPR管的曲面接触、变形、打滑和表面状态都会改变
该数值，所以配置中的 `b` 最终应由实验更新。钢珠质量 `4.09 g` 在加速度
模型中抵消，只在把阻力加速度换算成牛顿时使用。

## 2. 位置、速度和加速度

`ball_depth_tracker.py` 已输出加入 `0.005 m` 半径后的钢珠球心底座坐标。
控制器将用户标定的固定球心零位记为 `p0`，按要求计算：

```text
x = norm(p_ball_center_base - p0)
```

请把零点标定为“钢珠贴近原零点端时的球心底座坐标”，不要标成摄像头看到的
管道边缘像素。这个标定球心位于物理刻度0.5 cm、新坐标 `-12.0 cm`。

实际零点标定时，钢珠中心距离管道物理零边缘已有0.5 cm。对外控制坐标改为
以管道几何中心12.5 cm为0：朝原零点端为负，朝原25 cm端为正。因而零点
标定位置在新坐标中是 `0.5-12.5=-12.0 cm`。运行时统一换算：

```text
内部控制目标 = 新坐标输入目标 + 12.0 cm
```

因此 `--target-cm 0` 控制到管道几何中心，其内部位置是12.0 cm；标定点
`--target-cm -12.0` 对应内部位置0。球心两端各受0.5 cm半径限制，理论可达
输入范围为 `-12.0～+12.0 cm`。半径已经体现在标定点与中心的12.0 cm差值
中，运行时不能再次减去0.5 cm。

识别器在取到相机帧、进入YOLO前记录单调时钟。常加速度Kalman滤波器使用
实际可变采样间隔，由位置观测估计 `x、v、a`；控制主要使用低延迟的
`x、v`，加速度主要用于摩擦辨识和实验性扰动观测。不能直接用相邻两帧位置
二次差分作为控制加速度。

当前钢珠识别实测约 `15～20 FPS`。控制器只在一条带新采集时间且被Kalman
接受的视觉测量到达时更新一次；两帧之间保持上一倾角，不重复积分。25 Hz
循环只负责检查测量是否超时和更新终端状态，独立串口线程仍以50 Hz重发
最新倾角。因此“控制决策更新率”约为15～20 Hz，不应写成50 Hz。

## 3. 零点标定

将钢珠贴近原零点端，即让球心位于物理刻度0.5 cm、新坐标 `-12.0 cm`，
然后运行：

```bash
./H/start_ball_zero_calibration.sh
```

保持不动并按Enter。程序默认收集50个有效球心坐标，剔除离群点，把稳健
中位数写入：

```text
H/ball_control_config.json -> zero_point_base_m
```

需要无显示运行时：

```bash
./H/start_ball_zero_calibration.sh -- --no-display --no-cpu-fallback
```

`--` 后面的参数会原样传给 `ball_depth_tracker.py`。

`--startup-timeout-s`（默认60秒）只限制YOLO产生第一条结果前的等待时间；
收到第一条结果后，才开始计算 `--timeout-s`（默认30秒）的有效样本采集时间。
若出现大量 `NvMapMemAlloc... error 12` 且最终没有任何帧，这是Jetson统一
内存不足，不是零点或深度计算错误。先关闭其他占用GPU/内存的程序后重试。
若只需要完成静态零点标定，也可明确使用较慢但更稳的CPU模式：

```bash
./H/start_ball_zero_calibration.sh \
  --samples 50 \
  --timeout-s 180 \
  --startup-timeout-s 120 \
  -- \
  --device cpu \
  --no-display \
  --fps 30
```

CPU模式只建议用于静态标定，不用于15～20 FPS闭环控制。标定成功后程序会
打印 `零点标定完成`，并自动更新 `H/ball_control_config.json`；失败时不会
覆盖原零点。

## 4. 串级PID基线

必须先调通串级PID，再比较其他算法。

外环位置PI：

```text
e_x = x_ref - x
v_ref = clamp(Kpx*e_x + Kix*integral(e_x), -v_max, v_max)
```

内环速度PI：

```text
e_v = v_ref - v
theta_raw = -(Kpv*e_v + Kiv*integral(e_v))
```

负号来自本项目的机械定义：若目标在更靠电机的一侧，`e_v>0`，必须输出
负角度让钢珠远离零点。两级积分都有限幅，最终角度同时经过工作限幅和每个
新视觉帧最大变化量约束。

针对15～20 FPS和严格1 cm判负线，默认PID还包含：

- 制动速度包络：靠近目标时按剩余距离自动降低 `v_ref`；
  `braking_margin_m`采用连续软包络，增大时更早降速，但不会在目标之前把
  参考速度硬置0；
- 起滚补偿：普通误差下，球近乎静止时最小起滚角从0缓升到最多0.8°；
  它只作为PID同方向角度的下限，绝不与PID输出直接相加；
- 不再按距离强制输出固定大角度，远距离也由位置环、速度环和起滚补偿连续
  计算，避免5°命令使钢珠在有限视觉帧内快速越过目标；
- 两阶段到位：先停在目标来向侧0.6 cm，连续低速0.6 s后，再以
  0.1 cm/s的内部目标推进速度逐渐把偏置减到0.1 cm；
- 内部成功判据：误差不超过0.3 cm、速度不超过0.8 cm/s，并连续保持
  0.5 s；
- 电机保持死区：请求目标误差不超过0.3 cm且球速不超过0.8 cm/s时，保持
  上一电机位置并冻结PID积分；球仍高速通过死区时继续允许速度环制动。该值
  为 `cascade_pid.position_deadband_m=0.003`，可在实时UI修改并保存到方案；
  显式非零平衡角或车辆加速度前馈仍可越过位置死区更新执行器。该死区只对
  最终请求目标生效，不能把两阶段安全预停点前的剩余误差清零；
- 临时局部角度零点：目标外持续发送绝对值至少0.2°的非零倾角，但连续
  `local_zero_stall_time_s`（默认2.0秒）
  内位置变化不超过0.15 cm且球速不超过0.3 cm/s时，将扣除当前P项、静摩擦
  补偿和前馈后的保持偏置转入该管段临时零点，后续PID及静摩擦补偿仍叠加在
  它上面。局部零点最大绝对值1.2°，总
  输出仍受工作限角约束。运动过程中继续携带当前临时零点，不能按距离突然
  清零；新位置再次停滞时由当前倾角覆盖旧值。视觉失效、控制器重置、重新
  应用参数或程序退出时才遗忘。停滞时间可以在UI或参数方案中通过
  `local_zero_stall_time_s` 调整；学习到的临时角度本身不保存，也不建立位置
  历史表；
- 持续停滞增驱：局部零点判定成熟后，额外驱动力按
  `stall_drive_boost_ramp_deg_s` 缓慢增加，最大附加量由
  `stall_drive_boost_max_deg` 限制。每次刷新会把可吸收部分无扰转入局部
  零点，球重新运动后增驱项平缓退回0°；整个过程仍受工作倾角上限约束；
- 位置局部零点先验：位置模式启动或切换目标点时，先按基础配置
  `position_local_zero_prior.points` 估计目标附近的电机保持位移。目前
  `-5 cm -> +0.65 mm`、`+5 cm -> -1.5 mm`，两点之间线性插值、区间外夹紧
  最近端点，并按 `theta=atan(mm/250)` 换成内部角度。它只是初值；钢珠停滞
  达到 `local_zero_stall_time_s` 后仍由实际控制响应无扰覆盖；
- 比赛失败判据：从初始一侧接近后，一旦越过目标另一侧1 cm即锁存并报告
  失败，但默认不中断程序，继续输出回拉角度使钢珠返回目标。需要复现严格的
  “失败即停”行为时，显式增加 `--stop-on-competition-failure`。

默认时序和限制：

- 视觉触发控制更新：约15～20 Hz；
- 超时监督循环：25 Hz；
- 串口重复发送：50 Hz；
- 默认工作限角：`±2°`，PID反馈、位置保持角和加速度前馈叠加后的最终命令
  也受该限制；
- 每个新视觉测量最大角度变化：`0.25°`；
- 最大目标速度：`0.012 m/s`；
- 位置环比例增益为 `0.6 s^-1`，速度环比例增益为 `25 deg/(m/s)`、积分
  增益为 `4 deg/m`；固定远距离驱动关闭，静摩擦起滚补偿上限为0.8°且按
  1°/s缓慢建立，目标附近仍由速度反馈、积分保持角和制动逻辑控制；
- 超过 `0.25 s` 没有新鲜有效视觉测量：输出归零并清除连续稳定计时；
- 串口位移量程对应的倾角硬限位始终为 `±21.80°`。

实时记录必须含 `capture_monotonic_ms`。旧帧、重复/倒退时间戳、采集时间
超过0.25 s的结果都不能重新“续命”驱动电机。终端字段
`control_updated_from_new_vision` 可区分本周期是否真正更新了控制器。

视觉位置微抖会在求导后放大为速度尖峰。程序先由常加速度Kalman估计速度，
再按真实视觉时间戳通过时间常数 `0.12 s` 的一阶低通；速度环、目标到达判定、
默认终端 `vel`、完整遥测和实时曲线均使用该滤波速度。位置值不经过这层低通，
因此不会额外拖慢位置显示。视觉状态重置、超过1秒持续失视或速度环重新启动时
同时清空低通状态，防止旧速度带入新一轮控制。参数位于
`H/ball_control_config.json -> velocity_filter_time_constant_s`，增大更平滑但
滞后更大，减小响应更快但抖动更多。该项也在实时调参UI的“视觉速度滤波”
分区中，可实时应用并随参数方案保存。

低通之后还有静止感知钳零：连续0.4秒内球心位置跨度不超过0.0008 m（0.08 cm），
且滤波速度绝对值不超过0.001 m/s（0.10 cm/s）时，将速度置0并清除残余。该
门槛针对静止球约0.2～0.4 mm的位置抖动；明显运动时位置跨度会超限，仍保留
真实速度。三个固定项分别是 `velocity_stationary_window_s`、
`velocity_stationary_position_span_m` 和 `velocity_stationary_threshold_m_s`。

只计算、不驱动电机：

```bash
./H/start_ball_controller.sh \
  --target-cm 10 \
  --controller cascade_pid
```

`--target-cm` 可以省略，普通位置模式默认目标为管中心 `0 cm`：

```bash
./H/start_ball_controller.sh --enable-serial
```

单独调速度环时使用速度模式。它没有目标位置，绕过位置环、两阶段预停点和
位置死区；UI顶部改为设置 `-5～+5 cm/s` 目标速度：

```bash
./H/start_ball_controller.sh \
  --control-mode velocity \
  --target-speed-cm-s 0.5 \
  --enable-serial \
  --no-stream
```

速度模式仍保留速度PI、静摩擦补偿、倾角/变化率限制和临时局部角度零点。
目标速度非零但球连续`local_zero_stall_time_s`（默认2.0秒）几乎不动时，当前倾角仍会被学习为所在管段的局部
零点，并在运动中携带，到下一停滞管段再覆盖。速度模式初始暂停并输出0°，
设置速度后点击UI“启动速度环”，程序丢弃旧状态并在下一次有效钢珠检测后开始。

球心受半径限制理论可达约±12.0 cm，因此端点保护使用±11.5 cm阈值：正目标
速度到正端或负目标速度到负端时，停止更新速度PI并锁存触发前最后倾角；反向
离开端点不会误触发。锁存后点击“倾斜角返回0”会立即发送0°并暂停，局部角度
零点保留；随后必须再次点击“启动速度环”，重新检测到钢珠后才恢复跟踪。

默认会同时打开“钢珠串级PID实时调参”窗口。它在独立进程中运行，窗口卡顿或
关闭不会阻塞视觉控制和串口发送。所有输入框修改后必须点击按钮才生效：

- 顶部“运行目标点”支持滑条、数值输入和上下箭头；点击“应用目标点”后
  立即切换当前目标，无需重启。范围为 `-12.0～+12.0 cm`，切换时清除旧目标
  的PID积分、两阶段接近状态和到达/越界判定，从当前倾角平滑开始控制新目标；
- “应用到当前控制器（不保存）”：只对当前进程生效；
- “当前参数另存为”：输入文件名，保存到 `H/control_profiles` 并应用；
- “选择并应用”：加载下拉框所选JSON，同时把它设为下次启动默认；
- “重命名所选”：修改参数文件名；若它是默认方案，默认指向同步更新；
- “恢复启动值”：只恢复窗口输入框，仍需点击应用。

每次实时应用都会清除修改前累积的PID积分和两阶段接近状态，避免旧积分污染
新参数；倾角变化仍受新工作限角和每帧变化量约束。当前默认参数文件是：

两阶段接近在来向侧保留0.6 cm安全预停点。解除条件额外包含0.15 cm视觉
噪声余量，即最终误差不超过0.75 cm且连续低速0.6秒时开始缓慢推进；在尚未
进入最终0.3 cm电机保持死区时，即使距预停点不足原0.6 cm起滚门槛，静摩擦
补偿也会继续缓慢建立，避免小指令无法克服静摩擦而长期停住。

```text
H/control_profiles/low_oscillation_default.json
```

最后一次“选择并应用”或“当前参数另存为”的参数文件会在下次启动自动加载。
目标点属于本次运行指令，不写入PID参数文件；下次启动的初始目标仍由命令行
`--target-cm` 决定。
不需要界面时使用 `--no-control-ui`。命令行显式给出的
`--working-angle-limit-deg` 只临时覆盖本次启动值，除非随后从界面另存为方案。

程序还会默认打开第二个独立实时曲线窗口，使用类似VOFA的深色网格曲线：

- 位置模式包含“速度：目标/实际”和“位置：目标/实际”两个标签页；
- 速度模式只包含速度标签页，不绘制目标位置；
- 横轴使用视觉采样时间，显示最近30秒；速度单位cm/s、位置单位cm；
- 曲线进程通过有界非阻塞队列接收数据，绘图卡顿只会丢弃旧绘图点，不会
  阻塞视觉控制或50 Hz串口发送。

不需要曲线窗口时增加 `--no-plot-ui`。

控制器默认同时向 `192.168.50.199:5600` 推送原始视频。关闭推流：

```bash
./H/start_ball_controller.sh \
  --target-cm 10 \
  --controller cascade_pid \
  --no-stream
```

覆盖默认PC地址时，参数必须写在分隔符 `--` 前：

```bash
--stream-host 192.168.50.115
```

确认终端中位置、速度、角度方向正确后，才启用串口：

默认精简JSON使用 `tgt、pos、err、v_tgt、vel、deg、mm` 七个短字段；依次表示
目标位置、实际位置、位置误差、目标速度、实际速度、倾角和电机毫米位移。位置
单位cm、速度单位cm/s。两种速度同号且实际速度绝对值偏大时，速度环通常会给
反向倾角制动；失视时速度为 `null`。`--telemetry full` 仍使用完整字段名。

```bash
./H/start_ball_controller.sh \
  --target-cm 10 \
  --controller cascade_pid \
  --enable-serial
```

若需要无窗口或禁止CPU回退：

```bash
./H/start_ball_controller.sh \
  --target-cm 10 \
  --controller cascade_pid \
  --enable-serial \
  -- \
  --no-display \
  --no-cpu-fallback
```

以后加速度串口接入后，使用以下参数启用前馈：

```bash
./H/start_ball_controller.sh \
  --target-cm 0 \
  --controller cascade_pid \
  --enable-acceleration-feedforward
```

当前没有真实加速度数据时，开启该参数会明确提示“接口尚未接入”，并安全使用
0°前馈。现阶段可用恒定加速度做纯软件方向验证，不访问串口：

```bash
./H/start_ball_controller.sh \
  --target-cm 0 \
  --controller cascade_pid \
  --enable-acceleration-feedforward \
  --test-cart-acceleration-m-s2 1.0
```

其中 `+1.0 m/s²` 应产生负前馈倾角。该测试参数只用于软件验证，不能代替
比赛中的带时间戳实时加速度。使用 `--telemetry full` 可查看
`cart_acceleration_m_s2`、`acceleration_feedforward_deg` 和样本有效状态。

若已经知道当前目标位置大致需要的非零保持角，可作为本次运行初值传入：

```bash
./H/start_ball_controller.sh \
  --target-cm 5 \
  --controller cascade_pid \
  --equilibrium-angle-bias-deg 1.2
```

这只代表 `+5 cm` 目标的初值；换目标时可以传另一个值。省略时使用配置中的
0°初值，PID仍会通过积分自行学习局部保持角。完整遥测会显示
`equilibrium_angle_bias_deg`。

正角必须让终端中的 `position_cm` 下降。控制器默认限制为 `±2°`：

```bash
--working-angle-limit-deg 2
```

仅在专门实验中确认确有必要时才显式增大；协议最大允许21.80°，但比赛控制
默认不会使用该上限。

终端出现 `competition_failure` 只表示本次任务曾越过比赛的1 cm底线；
`competition_failed` 会保持为 `true` 便于赛后统计，即使钢珠已经回到目标。
默认控制器仍继续工作。只有启动时加入以下参数才会立即输出0°并退出：

```bash
--stop-on-competition-failure
```

默认终端状态改为约每秒1行精简JSON，只显示有效性、目标、位置、偏差、速度
和最终量化角度命令。需要关闭输出：

```bash
--print-every 0
```

需要恢复全部滤波、时序、补偿及串口字节字段：

```bash
--telemetry full --print-every 5
```

### 实机调参诊断开关

串级PID实机运行时可增加 `--tuning-debug`：

```bash
./H/start_ball_controller.sh \
  --target-cm 20 \
  --controller cascade_pid \
  --enable-serial \
  --tuning-debug \
  -- \
  --no-display \
  --no-cpu-fallback
```

这个开关默认关闭。打开后只观察新鲜且被Kalman接受的视觉控制更新，不修改
配置文件、PID状态、倾角指令或串口数据。诊断在独立后台线程运行；控制线程
只替换一份最新数字快照，终端输出变慢时丢弃旧诊断快照而不阻塞控制。为避免
两套终端输出共同造成卡顿，开启调参诊断时普通 `--print-every` JSON自动停用。

终端每2秒输出一条 `[调参监视]`，包括：

- 识别程序处理FPS、有效控制更新FPS和测量接受率；
- 测量年龄中位数/P95、识别处理耗时P95；
- 球位置、要求目标、实际误差和两阶段内部控制误差；
- 球速度、外环参考速度、最终发送倾角和到位状态。

处理FPS使用识别记录的帧号差计算，因此中间漏检仍计入识别程序处理量；有效
FPS使用控制线程的有效测量累计序号计算，因此即使后台为防阻塞丢弃了旧诊断
快照，统计也不会变低。这样能区分“YOLO本身变慢”和“YOLO仍快但漏检、深度
无效或测量被离群门控拒绝”。启动后若一直没有有效球位置，后台仍每2秒输出
最近帧号、无效原因和处理耗时，不会出现调试开关打开后终端长期没有信息。

诊断会对同一种建议做6秒冷却，并在证据足够时输出
`[调参建议][级别][事件]`：

- `low_vision_fps / low_vision_acceptance / high_vision_delay /
  vision_gaps`：先处理视觉性能、漏检或旧帧，不用增大PID来补延迟；
- `direction_mismatch`：球持续反向运动，立即停止，先核对正角使位置减小、
  零点和串口符号；
- `stiction`：经过起滚补偿爬升仍不动，建议下一次试验只小幅修改静摩擦
  补偿或爬升速度；
- `approach_too_fast`：根据错误侧1 cm余量和当前速度估计越界风险，优先
  降低最大速度，再单独降低制动速度包络参数；当前0.6 cm预停偏置已经等于
  二阶段细化解锁误差，不能再增加，否则可能无法进入最终目标；
- `target_oscillation`：内部误差多次有效换向且摆幅不衰减，优先降低位置
  外环增益；
- `response_slow`：球方向正确但长期明显跟不上参考速度，再考虑小幅增加
  速度积分。

只有真实启用串口时，诊断器才会根据实际运动给出不起滚、方向反、接近过快、
振荡或响应慢等闭环参数建议；安全试运行不会把“没有驱动电机”或手动移动球
误判成控制器问题。视觉时序不健康时也会暂停普通PID增益建议。退出时打印
本次处理/有效FPS、接受率、位置范围、最大测量年龄、是否曾稳定及建议事件
汇总。

建议每次只改一个参数并完整重复同一目标实验；诊断不会自动写入
`ball_control_config.json`。`--tuning-debug` 当前只支持串级PID，实验性
MPC仍应先做离线回放和模型辨识。

## 5. 第二套算法：约束MPC

项目提供束搜索非线性MPC作为实验对照。它直接预测未来角度序列，并原生满足：

```text
-working_limit <= theta_i <= +working_limit
abs(theta_i - theta_(i-1)) <= max_angle_step
```

每个预测步只尝试有限个角度增量，每层保留代价最低的96条路径。默认18步
预测时域在当前Jetson上的纯控制基准约 `10～15 ms`，低于15 FPS视觉间隔
`66.7 ms`；没有CVXPY/OSQP依赖。代价同时惩罚位置误差、速度、角度和角度变化，
并对预测越出内部管长范围强惩罚；对外球心目标仍限制为
`-12.0～+12.0 cm`。

在完成10°滚落模型标定后试运行：

```bash
./H/start_ball_controller.sh \
  --target-cm 10 \
  --controller mpc
```

先保持无串口试运行，再加 `--enable-serial`。视觉加速度驱动的常值扰动观测
默认关闭，因为初期加速度估计噪声可能反而使控制变差；完成滤波验证后才考虑
`--enable-mpc-dob`。

MPC比LQR更值得作为第二方案，因为25 cm范围内倾角可达21.80°，而MPC能直接使用
`sin(theta)` 非线性和角度/变化量约束。LQR可作为平衡点附近的简化对照，但
与串级PID相比新增价值较小。滑模控制容易把视觉噪声变成角度抖振，本装置不
作为优先方案。

当前MPC仍使用未辨识的名义模型。15～20 FPS不确定性随机仿真20次时有17次
越过1 cm判负线，因此现在只能保留为实验代码，不能直接上实机。完成滚动
参数、角度零偏和延迟标定后，再重新调MPC权重并与PID做相同回放对比。

## 6. 离线仿真与当前结论

仿真不打开相机、串口或电机。非线性被控对象随机覆盖：

- 视觉15～20 FPS、延迟40～120 ms、位置噪声0.8～2.5 mm、丢帧0～6%；
- 有效重力增益5.0～8.5 m/s²；
- 库仑/滚动阻力0～0.30 m/s²、黏性阻力0～0.8 s⁻¹；
- 恒定偏置加速度 `-0.10～+0.10 m/s²`；
- 双向3～21 cm移动。

运行随机验证：

```bash
./.conda/envs/yolo-steel-ball/bin/python \
  H/simulate_ball_control.py \
  --controller cascade_pid \
  --trials 100 \
  --duration-s 20 \
  --seed 271828
```

独立种子 `271828` 和 `20260817` 各100次，共200次均未越过1 cm；其中
115次在20秒内最终连续进入内部±0.3 cm低速稳定条件。两批中最坏错误侧
越过量为0.943 cm，较差一批的95分位为0.536 cm。这只是当前随机分布内的
数值结果，不是实机保证。

运行固定联合边界压力测试：

```bash
./.conda/envs/yolo-steel-ball/bin/python \
  H/simulate_ball_control.py \
  --controller cascade_pid \
  --stress-test \
  --duration-s 20 \
  --seed 20260817
```

压力测试把15 FPS、120 ms、2.5 mm噪声、6%丢帧与动力学参数各端点同时
组合。当前结果仍有4/8次越过1 cm，最坏1.069 cm，说明在真实摩擦和滚动
增益尚未测量前，无法诚实声称对整个假设范围保证成功。实物试验必须先缩小
参数范围，再重新仿真；不要为了让压力测试数字好看而继续盲目放大起滚角。

## 7. 10°滚落实验

先完成零点标定。把管道稳定在 `+10°`，钢珠静止放在电机端一侧，运行：

```bash
./H/start_pipe_friction_calibration.sh --angle-deg 10
```

识别器出现首个有效位置后，终端才会提示释放。按Enter后立即无初速度释放
钢珠。程序记录原始球心轨迹，自动寻找远离端点的连续滚动段，用稳健二次轨迹
拟合估计净加速度，并在 `H/output` 保存CSV和JSON。

若接受本次单角度集总增益并写入MPC模型：

```bash
./H/start_pipe_friction_calibration.sh \
  --angle-deg 10 \
  --update-model
```

一次 `+10°`、单方向实验只能得到：

- 该工况净加速度；
- `净加速度/sin(10°)` 的经验集总角度增益；
- 在质点假设或理想实心球假设下的等效损耗参考值。

它不能唯一分离：

- 理想滚动惯量系数；
- 库仑/滚动阻力；
- 黏性阻力；
- 静摩擦；
- 管道零角偏差。

25 cm、10°条件下滚动时间可能不到1秒。当前15～20 FPS通常只有约10～15个
有效点，所以至少重复10次并保留每次原始轨迹；若拟合残差太大，可增加较小
倾角实验延长滚动时间。更完整模型应测
`±5°、±10°、±15°`，每个方向至少3次。

## 8. 需要测量或标定的性质

按优先级排列：

1. 球心贴近原零点端（新坐标-12.0 cm）时的底座三维坐标；
2. 实际可达球心范围是否接近-12.0～+12.0 cm；
3. 电机命令0°时管道是否真正水平；
4. 发送 `+2°` 时小球位置是否下降，确认正负号；
5. 钢珠静止时位置噪声标准差和偶发深度离群；
6. 有效视觉频率、推理延迟和连续丢帧时间；
7. `+10°` 下滚净加速度及多次重复离散性；
8. 正负方向开始持续滚动的临界角，用于判断静摩擦和方向不对称；
9. `±5°、±10°、±15°` 的角度—加速度关系；
10. 不同速度下减速度变化，用于判断速度相关阻力；
11. 管道局部接缝、弯曲、粗糙度是否造成特定位置卡滞；
12. 实际可接受的角度变化率和靠近端点时的安全制动能力。

钢珠质量已经记录为 `0.00409 kg`。还应记录钢珠实际直径、PPR管外径/槽形、
钢珠与管道的接触形式及表面材料；这些比质量更直接影响滚动惯量和阻力。

## 9. 单片机串口协议

串口帧固定为8个原始字节：

```text
[0x92, sign, integer, hundredths, 0, 0, 0, 0x29]
```

每次打开串口后，在第一帧角度命令之前先发送一次电机使能帧：

```text
92 4F 4B 00 00 00 00 29
```

紧接着发送一次0°初始化帧：

```text
92 00 00 00 00 00 00 29
```

其中 `0x4F 0x4B` 是ASCII大写字符 `O`、`K`。完成“使能一次、零位一次”后
才开始50 Hz目标位移发送；同一次串口连接中不重复初始化，重新打开
串口会重新执行该序列。

控制器计算的倾角只用于终端显示和内部控制。串口发送前采用理想几何关系：

```text
motor_displacement_mm = 250 * tan(angle_deg * pi / 180)
```

正倾角得到正位移，表示电机抬高；负倾角得到负位移，表示电机下降；0°对应
电机零位。协议字段含义为：

串口符号现已恢复为正常方向，公共开关
`H/angle_serial.py::SERIAL_SIGN_INVERTED=False`。PID/MPC、终端和线上毫米数
的正负定义一致；使能帧和零位帧不受该开关影响。

- 帧头固定为 `0x92`；
- `sign=0x00`：正；
- `sign=0x01`：负；
- `integer`：升降毫米数整数部分的二进制值；
- `hundredths`：升降毫米数两位小数的二进制值；
- 帧尾固定为 `0x29`；
- 实际编码严格限制在 `±99.99 mm`，倾角接口限制为 `±21.80°`。

示例：

```text
+10.00° -> +44.08 mm -> 92 00 2C 08 00 00 00 29
-10.00° -> -44.08 mm -> 92 01 2C 08 00 00 00 29
+21.80° -> +99.99 mm -> 92 00 63 63 00 00 00 29
```

单次协议测试：

```bash
./.conda/envs/yolo-steel-ball/bin/python \
  serial/send.py 2.00 --once
```

持续50 Hz发送：

```bash
./serial/start_send.sh 2.00
```

指定串口或发送频率：

```bash
./serial/start_send.sh 2.00 \
  --port /dev/ttyUSB0 \
  --baud 9600 \
  --rate-hz 50
```

它会先发送一次电机使能帧和一次零位初始化帧，随后持续发送换算后的目标
升降位移；按
Ctrl+C后停止周期线程并发送最终0°。`--once` 仅用于协议测试，只发送使能帧、
零位初始化帧和一帧由指定角度换算出的位移：

```bash
./serial/start_send.sh -2.50 --once
```

更适合实机逐角度测试的交互工具：

```bash
./H/start_motor_angle_test.sh
```

启动后输入 `2`、`-2`、`0` 等角度并按Enter，输入 `q` 或按Ctrl+C会先停止
周期线程，再同步发送最终0°。测试脚本默认只允许 `±10°`；确认机构安全后可用
`--limit-deg 21.8` 扩大，但绝不允许超过 `±21.80°`。终端同时显示换算后的
电机升降毫米数。也可直接持续发送一个
目标角：

```bash
./H/start_motor_angle_test.sh 2.5
```

控制器保持串口只打开一次，由独立线程以50 Hz重复最新目标位移，不受视觉帧率
抖动影响。持续发送工具和闭环控制器在正常退出时都会额外发送一次0°。
9600 baud、8N1下50 Hz八字节约占4000 bit/s，带宽足够。

单片机端应搜索帧头 `0x92`，收满8字节后验证帧尾 `0x29`；帧尾错误时重新
寻找下一个帧头。系统中只能有一个串口发送进程。

监听单片机回传数据请使用项目环境启动入口：

```bash
./serial/start_receive.sh
```

原始模式会打印收到的全部字节；若单片机回传协议仍为项目原定义的
`0x76 + 6字节 + 0x67`，可使用：

```bash
./serial/start_receive.sh --framed
```

该接收帧与电机下发的 `0x92 ... 0x29` 是两个方向的协议，不要混用。

`serial/send.py` 的协议编码没有问题，但旧退出顺序存在后台线程缓存旧非零帧
并在归零帧之后补发的竞争窗口。现已统一改为：先把待发角设为0°、停止后台
线程、最后同步发送0°；`--once` 仍按其字面含义只发送指定的一帧，不会自动
追加0°。
